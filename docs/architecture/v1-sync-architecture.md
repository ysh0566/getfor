# 第一版同步架构

状态：已确认

## 范围与假设

- 第一版客户端只覆盖 macOS 和 Android；iOS、Windows 暂缓。
- Apple Passwords 集成只支持 macOS 26 及以上。
- 不使用云端、中继服务器或账号中心；设备只在同一局域网内互传。
- “同步到 Apple Passwords”指用户确认的一次性写入，不代表后台双向同步。

## 第一版功能

1. 在 macOS 26+ 通过 Credential Exchange 批量导入 Apple Passwords 数据。
2. 导入完成后提示设置本产品为默认 AutoFill Provider，同时提供明显的“取消”操作。
3. 在本产品中新建密码时显示“保存后导出到 Apple Passwords（下一步需选择 Apple Passwords）”选项，默认开启。
4. 选项开启时先保存到本产品，再启动单条 Credential Exchange；用户需要在系统界面自行选择并确认 Apple Passwords。
5. macOS 与 Android 设备通过局域网发现、配对并同步本产品保险库。

## Apple Passwords 边界

macOS 不提供第三方密码管理器静默写入 Apple Passwords 的公开 API。第一版使用 `ASCredentialExportManager` 导出单条 CXF 凭据，系统界面负责选择接收方和本地认证。

因此 UI 使用“保存后导出到 Apple Passwords（下一步需选择 Apple Passwords）”，不使用“自动同步到 Apple Passwords”：

- 用户关闭选项：只保存到本产品。
- 用户开启并完成系统流程：只能标记为“系统导出流程已完成”；公开 API 不返回最终接收方的持久化结果。
- 用户取消或系统失败：本产品中的保存仍然成功，标记为“未完成导出”，允许手动重试。
- 不后台重试 Credential Exchange，避免反复弹出系统界面。

## 局域网同步

```text
设备启动或回到前台
        |
        v
mDNS / DNS-SD 发布并发现 _getfor._tcp.local
        |
        v
只连接已经配对且公钥指纹匹配的设备
        |
        v
相互交换缺失的加密变更记录
        |
        v
应用变更；并发修改保留冲突副本
```

### 服务发现

- mDNS 只广播协议版本、随机设备 ID 和端口。
- 不广播用户名、保险库名称、条目数量或任何凭据元数据。
- Apple 平台使用 Bonjour；其他平台使用兼容 DNS-SD 实现。
- 广播只能发现设备，不能作为身份认证依据。

### 首次配对

- 新设备展示二维码，包含设备公钥指纹和一次性配对秘密。
- 已有设备扫描并要求双方确认。
- 配对通道认证成功后，才传递由新设备公钥封装的保险库密钥。
- 移除设备后为剩余设备轮换保险库密钥；已经落到被移除设备上的历史明文无法远程撤回。

### 传输与数据模型

- 使用 TLS 1.3，并固定已配对设备的证书或公钥。
- 每次变更包含随机操作 ID、源设备 ID、设备内递增序号、目标条目 ID、基础版本和加密负载。
- 删除使用墓碑记录，防止离线设备重新带回已删除条目。
- 同一基础版本的并发修改不静默覆盖；保留一个冲突副本让用户选择。
- 第一版直接采用设备间两两同步，不引入 leader、中心节点或 CRDT。

### Android 限制

- 桌面端可在应用运行时持续发布服务。
- Android 端在应用前台、刚进入后台的短窗口或系统授予的后台任务中同步。
- 不承诺 Android 应用被挂起或强制退出后仍持续广播；再次打开应用时自动补齐变更。

## 安全与可靠性要求

- RPO：任一已完成本地保存的变更不得因同步失败而丢失。
- 所有同步均为可重试操作；网络中断不回滚本地保存。
- 未配对设备即使发现服务，也不能读取协议内容或保险库数据。
- 保险库数据在磁盘和传输中始终加密。
- Apple 导出流程与局域网同步分别记录状态，互不影响；产品不声称能确认 Apple Passwords 已持久化。

## 明确不做

- Apple Passwords 后台增量读取或双向同步。
- 私有 Keychain/Passwords 数据库解析。
- 互联网同步、云备份、穿透、固定公网服务。
- 自动合并并发密码值。
